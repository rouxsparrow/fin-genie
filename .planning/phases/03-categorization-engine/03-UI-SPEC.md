# Phase 3 — UI Design Contract

> Visual and interaction contract for the Categorization Engine phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Inline rule creation popover on review screen, real-time rule evaluation with categorized/uncategorized split, 100% categorization gate on import bar, rules management page with reorder/edit/delete, categories management page with inline editing, re-categorize flow, system rule for card payments, sidebar nav enablement for Rules and Categories.
>
> **Inherits from:** Phase 1 UI-SPEC (`01-UI-SPEC.md`) and Phase 2 UI-SPEC (`02-UI-SPEC.md`) -- all spacing, typography, color, interaction states, and Neo Brutalism styling tokens carry forward. This document only declares additions and phase-specific contracts.

| Property | Value |
|----------|-------|
| Tool | shadcn/ui + neobrutalism registry |

| Component library | Radix UI (via shadcn primitives) |

## Page Layouts

### Review Screen Modifications (`/import` -- State 4: Review)

Phase 3 modifies the Phase 2 review screen. Layout structure is unchanged. Modifications are:

#### Categorized/Uncategorized Split (Real Data)

The Phase 2 placeholder (`false` on line 36 of review-screen.tsx) is replaced with actual rule evaluation. After parsing, all rules are fetched and evaluated client-side against parsed transactions. Transactions matching a rule appear in the "Categorized" section with their category badge. Transactions matching no rule appear in "Uncategorized".

- Categorized transactions show a Badge (amber bg, `variant="default"`) with the category name in the Category column.
- Card payment transactions (matched by the system "PAYMENT" rule) show a Badge (`variant="neutral"`, grey bg) labeled "Card Payment" with a `Lock` icon (12px) to indicate system categorization.

#### Clickable Uncategorized Rows (D-01)

- Uncategorized transaction rows in the desktop table gain `cursor-pointer` and a hover state (`bg-background` tint).
- Clicking an uncategorized row opens the RuleCreationPopover anchored to that row.
- On mobile, tapping an uncategorized TransactionCard opens the same popover (positioned as a bottom sheet via popover with `side="top"`).
- Only one popover can be open at a time. Opening a new one closes the previous.

#### Rule Creation Popover (D-01, D-02, D-03)

A compact Radix Popover anchored to the clicked transaction row.

**Popover layout (320px width on desktop):**
- 16px padding on all sides
- Field 1: **Pattern** (Label + Input)
  - Label: "Pattern" (14px/700)
  - Input: text input pre-filled with smart extraction (D-02)
  - 4px gap below label, 12px gap below input
- Field 2: **Match Type** (Label + two-button toggle group)
  - Label: "Match Type" (14px/700)
  - Two buttons side-by-side: "Substring" (selected default, amber bg) | "Regex" (unselected, white bg)
  - Each toggle button: 14px/500, 2px border, `rounded-base`, 32px height
  - 4px gap below label, 12px gap below buttons
- Field 3: **Category** (Label + Select dropdown)
  - Label: "Category" (14px/700)
  - Select shows existing categories sorted alphabetically
  - Last item in dropdown: "+ Create new category" (14px/500, amber text `text-main`)
  - If "Create new" is selected, Select is replaced by an Input for the new category name with a small "Create" button inline
  - 4px gap below label, 16px gap below select
- Actions row (flex, justify-end, 8px gap):
  - "Cancel" button (`variant="neutral"`, 14px)
  - "Save Rule" button (`variant="default"`, amber bg, 14px)

**Pattern pre-fill heuristic (D-02):**
- Strip known location suffixes: "SINGAPORE SG", "SG", "SINGAPORE", country codes
- Strip trailing card numbers (e.g., "XXXX1234")
- Take the first meaningful phrase. Example: "GRAB TRANSPORT SINGAPORE SG" pre-fills as "GRAB".
- Admin can freely edit the pre-filled pattern.

**Real-time feedback (D-04):**
- After saving a rule, ALL matching transactions across both sections immediately re-evaluate.
- Transactions that now match move from the "Uncategorized" section to "Categorized".
- Section count badges update instantly.
- A brief toast confirms: "Rule created. {N} transactions categorized."

#### 100% Categorization Gate (D-07)

The import bar at the bottom of the review screen is modified:

**When uncategorized transactions exist:**
- Import button is disabled (50% opacity, no shadow, `cursor-not-allowed`)
- Left text shows progress: "{categorized}/{total} categorized -- categorize all to import" (16px/500)
- A small progress bar (4px height, amber fill, black 2px border) spans below the text, width proportional to categorization percentage

**When 100% categorized (all non-duplicate transactions have a category):**
- Import button is enabled: amber bg, "Import {N} Transactions" label
- Left text shows: "{N} transactions ready" (16px/700)
- Progress bar is full (100% amber fill)

**Card payment auto-categorization (D-08):**
- System rule matching "PAYMENT" auto-categorizes card payment transactions on first rule evaluation.
- These transactions count as "categorized" for the 100% gate.
- They show a "Card Payment" badge with `Lock` icon, distinguishing them from user-categorized transactions.

### Rules Page (`/rules`, admin only) (D-10)

- Page heading: "Rules" (24px/700)
- Action row (flex, items-center, justify-between):
  - Left: descriptive text "Rules evaluate top-to-bottom. First match wins." (14px/500, 60% opacity)
  - Right: two buttons with 8px gap:
    - "Re-categorize All" button (`variant="default"`, amber bg) (D-13)
    - "Add Rule" button (`variant="default"`, amber bg)
- 24px gap
- Rules table (full details below)

**Rules Table (D-10):**
- Neo Brutalism Table component
- Columns: Order | Pattern | Match Type | Category | Actions
- Column headers: 14px/700
- Order column: sort_order number (14px/500, `tabular-nums`), width 60px
- Pattern column: rule pattern text (14px/500, `font-mono`), flex-grow, max-width 300px with truncation
- Match Type column: Badge component, width 100px
  - "substring" -- Badge `variant="neutral"` (white bg, black border)
  - "regex" -- Badge `variant="neutral"` with `font-mono` text
- Category column: category name (14px/500), width 160px
- Actions column: flex row with 8px gap, width 140px
  - Reorder: `ChevronUp` and `ChevronDown` icon buttons (20px icons, 32px button size, `variant="neutral"`)
  - `ChevronUp` disabled on first user rule; `ChevronDown` disabled on last user rule
  - `Pencil` icon button (edit trigger, 20px icon, 32px button, `variant="neutral"`)
  - `Trash2` icon button (delete trigger, 20px icon, 32px button, `variant="neutral"`, hover: red text)
- Row height: 48px
- Alternating row backgrounds: odd rows `bg-secondary-background`, even rows `bg-background`
- System rules rendered at the top with `Lock` icon (14px) before the pattern, 40% opacity on actions column (reorder/edit/delete disabled), subtle `bg-background` tint

**Inline Rule Editing (D-11):**
- Clicking the Pencil icon on a rule row expands that row into an edit form below.
- The original row stays visible but at 40% opacity.
- Edit form (same width as table, 16px padding, white bg, 2px border-t dashed):
  - Three fields in a horizontal flex row (desktop) or stacked (mobile):
    - Pattern: Input with current value (flex-grow)
    - Match Type: two-button toggle (same as popover, 140px)
    - Category: Select dropdown (200px)
  - Action row below fields (flex, justify-end, 8px gap, 8px margin-top):
    - "Cancel" button (`variant="neutral"`)
    - "Save Rule" button (`variant="default"`, amber bg)
- Only one row can be in edit mode at a time. Opening edit on another row auto-cancels the previous.

**Delete Rule (D-12):**
- Clicking `Trash2` removes the rule immediately (optimistic UI).
- A toast appears: "Rule deleted. {N} transactions affected." with an "Undo" action button.
- Undo reverts the deletion within the toast auto-dismiss window (5 seconds for destructive toasts).
- If the rule being deleted is a system rule, the `Trash2` button is disabled and shows a tooltip: "System rules cannot be deleted."

**Mobile (< 768px):**
- Rules table transforms to stacked cards.
- Each rule card: Card component with 16px padding.
  - Top row: sort order number + pattern (`font-mono`, 14px/700, truncated)
  - Middle row: match type Badge + category name
  - Bottom row: action buttons (reorder arrows + edit + delete) in a flex row
- Reorder uses `ChevronUp`/`ChevronDown` buttons (same as desktop).
- Edit expands the card to show the edit form below the card content.

**Empty state:**
- Uses existing `EmptyState` component
- Icon: `ListFilter` from lucide
- Heading: "No rules yet"
- Body: "Create your first rule to start categorizing transactions automatically."
- CTA: "Add Rule" (amber accent button)

### Categories Page (`/categories`, admin only) (D-14)

- Page heading: "Categories" (24px/700)
- Descriptive text: "Categories organize your transactions. Assign rules to categories to auto-categorize imports." (14px/500, 60% opacity)
- 24px gap
- Categories list (card container)

**Categories List (D-14):**
- White bg card (`--secondary-background`), 2px border, `rounded-base`, no shadow (flat list)
- Each category item is a row inside the card:
  - Height: 48px
  - Separator: 1px border-b between items (last item has no border)
  - Flex row, items-center, 16px horizontal padding
  - Left: category name (16px/500)
  - Right: action buttons
    - System categories (`is_system: true`): `Lock` icon (16px, 40% opacity) + tooltip "System category"
    - User categories: `Pencil` icon button (edit) + `Trash2` icon button (delete)
    - Icon buttons: 32px square, `variant="neutral"`

**Inline Edit-in-Place (D-14):**
- Clicking `Pencil` replaces the category name text with an Input containing the current name.
- The `Pencil` and `Trash2` buttons are replaced by `Check` (save) and `X` (cancel) icon buttons.
- Enter key saves, Escape key cancels.
- Input auto-focuses on edit activation.

**Delete Category:**
- Clicking `Trash2` checks if any rules reference this category.
- If rules exist: toast error "Cannot delete '{name}'. {N} rules use this category. Remove or reassign those rules first."
- If no rules: category is deleted immediately (optimistic UI) with toast "Category '{name}' deleted." and "Undo" action.
- System categories (`is_system: true`): `Trash2` is disabled, tooltip shows "System categories cannot be deleted."

**Add Category (D-14):**
- "Add Category" button at the bottom of the list card (inside the card, full width, `variant="neutral"`, dashed top border).
- Clicking it appends a new empty row at the bottom of the list with an auto-focused Input.
- Enter or clicking `Check` saves the new category. Escape or clicking `X` removes the empty row.
- Validation: category name must be non-empty and unique within the household. Duplicate names show inline error text below the input: "A category with this name already exists." (14px, `#ef4444`).

**Empty state:**
