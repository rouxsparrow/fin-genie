# Phase 2 — UI Design Contract

> Visual and interaction contract for the PDF Import Pipeline phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** PDF upload drop zone, parsing progress state, transaction review screen (split categorized/uncategorized), statement summary card, duplicate detection overlay, bottom sticky import bar, import history table, statement period timeline bar, bank config read-only viewer, error card for parse failures.
>
> **Inherits from:** Phase 1 UI-SPEC (`01-UI-SPEC.md`) — all spacing, typography, color, interaction states, and Neo Brutalism styling tokens carry forward. This document only declares additions and phase-specific contracts.

---

| Property | Value |

Exceptions:
- Drop zone has a minimum height of 240px (idle state) to create a prominent upload target.

- Timeline bar segment height is 32px.
- Mobile content area uses 16px padding (inherited from Phase 1).

## Typography

Inherited from Phase 1. No new roles needed.

| Role | Size | Weight | Line Height | Phase 2 Usage |
|------|------|--------|-------------|---------------|
| Body | 16px | 500 (medium) | 1.5 | Transaction descriptions, summary values, error card body, drop zone instruction text |
| Label | 14px | 500 (medium) | 1.4 | Table cells (date, amount), column headers use 14px/700, badge text, timeline month labels, "Upload another" link |
| Heading | 24px | 700 (bold) | 1.2 | Page titles ("Import Statement", "Import History"), section headers ("Categorized", "Uncategorized"), summary card title |
| Display | 32px | 700 (bold) | 1.1 | Not used in Phase 2 |

**Additional typographic rules for this phase:**
- Transaction amounts use tabular-nums (`font-variant-numeric: tabular-nums`) for column alignment.
- Amounts are right-aligned in table cells.
- Credit amounts (refunds) display in parentheses: `($12.50)` with the same foreground color -- no color change for credits vs debits in the review table.
- Duplicate transaction rows use `line-through` text decoration at 50% opacity.

## Color

Inherited from Phase 1. Phase 2 introduces two semantic section colors for the categorized/uncategorized split (D-07).

| Role | CSS Variable / Value | Usage |
|------|---------------------|-------|
| Dominant (60%) | `--background` / `oklch(96.22% 0.0569 95.61)` | Page background, content area surface |
| Secondary (30%) | `--secondary-background` / `oklch(100% 0 0)` | Cards, table backgrounds, drop zone background, summary card, sticky bar |
| Accent (10%) | `--main` / `oklch(84.08% 0.1725 84.2)` | See reserved-for list below |
| Foreground | `--foreground` / `oklch(0% 0 0)` | Body text, headings, icons, table text |
| Border | `--border` / `oklch(0% 0 0)` | All borders (2px solid), box shadows |
| Destructive | inline `#ef4444` | Error states only (parse failure card border accent) |

### Phase 2 Semantic Colors

| Color | Value | Usage |
|-------|-------|-------|
| Categorized section accent | `#16a34a` (Tailwind `green-600`) | Left border (4px) on the "Categorized" section header badge, filled timeline segments |
| Uncategorized section accent | `#d97706` (Tailwind `amber-600`) | Left border (4px) on the "Uncategorized" section header badge |
| Duplicate row | `--foreground` at 50% opacity | Strikethrough text, faded row for duplicate transactions |
| Gap highlight | `#ef4444` (Tailwind `red-500`) | Empty/missing month segments in the timeline bar |

These semantic colors are NOT applied to backgrounds or large surfaces. They are used exclusively as thin left-border accents on section badges and as small indicators in the timeline bar.

### Accent Reserved For (Phase 2 additions)

The amber accent (`--main`) is used on these additional elements in Phase 2:

1. **"Import {N} Transactions" button in sticky bar** -- primary action to confirm import (amber bg, disabled state when uncategorized transactions exist)
2. **"Upload another" link** -- amber text-decoration underline on hover
3. **Active "Import" sidebar nav item** -- amber background (inherited pattern)
4. **Drop zone icon** -- `Upload` icon uses amber (`text-main`) at 48px
5. **Filled timeline segments** -- months with imported data use `green-600` (NOT amber) to distinguish "data exists" from "action available"

Accent is NOT used on: section header backgrounds, table row backgrounds, timeline bar backgrounds, or error states.

## Page Layouts

### Import Page (`/import`)

**State machine:** The import page has 5 visual states, managed by client-side state.

#### State 1: Idle (Drop Zone)

- Page heading: "Import Statement" (24px/700)
- Full-width drop zone container below heading with 16px gap
- Drop zone: white background (`--secondary-background`), 2px dashed black border, `rounded-base`, minimum height 240px, centered content
- Drop zone content (vertically centered):
  - `Upload` icon from lucide (48px, amber `text-main`)
  - 16px gap
  - "Drag your PDF here or click to browse" (16px/500, 60% opacity)
  - 8px gap
  - "Citibank SG credit card statements only. Max 4MB." (14px/500, 40% opacity)
- Entire drop zone is clickable (opens file picker)
- Drop zone hover: border-color transitions to amber (`--main`), cursor pointer

#### State 2: Drag Active

- Drop zone border changes from dashed to solid, color changes to amber (`--main`)
- Background gains a subtle amber tint: `bg-main/5` (5% amber overlay)
- Text changes to "Drop PDF to upload" (16px/500, full opacity)
- Icon scales up to 56px with 200ms ease transition

#### State 3: Parsing (Progress)

- Drop zone collapses to a compact bar: "Uploading statement.pdf..." (16px/500) with a `Loader2` spinner icon (20px, `animate-spin`)
- Below the compact bar, skeleton loaders mimic the review screen layout:
  - 1 skeleton card (summary card shape): 100% width, 120px height
  - 16px gap
  - 6 skeleton table rows: 100% width, 48px height each, 4px gap between rows
- Skeleton uses the existing `Skeleton` component (pulse animation, 2px border)

#### State 4: Review (Parsed Results)

- Compact summary bar replaces drop zone: white bg, 2px solid border, 16px padding, single line
  - Left: `FileText` icon (20px) + "statement.pdf" (14px/700) + " -- 15 transactions parsed" (14px/500)
  - Right: "Upload another" link (14px/500, amber underline on hover)
- 16px gap
- Statement summary card (full details below)
- 16px gap
- Duplicate warning banner (only if duplicates detected, full details below)
- 16px gap
- "Categorized" section (full details below)
- 16px gap
- "Uncategorized" section (full details below)
- Bottom sticky import bar (full details below)

#### State 5: Error

- Drop zone is replaced by an error card (full details in Copywriting Contract)
- Error card uses the same Card component with a 4px left border in red (`#ef4444`)

### Statement Summary Card

A Card component at the top of the review screen (D-09).

- Card with standard Neo Brutalism styling (2px border, 4px shadow)
- Card content arranged as a 2x2 grid on desktop, single column on mobile:
  - **Statement Period:** "1 Mar - 31 Mar 2026" (16px/500 value, 14px/500 "Statement Period" label above)
  - **Total Transactions:** "15" (16px/700 value, 14px/500 label above)
  - **Total Debits:** "$1,234.56" (16px/700 value, 14px/500 label above)
  - **Total Credits:** "($89.00)" (16px/700 value, 14px/500 label above)
- Grid gap: 24px horizontal, 16px vertical
- Card padding: 24px

### Transaction Sections (Categorized / Uncategorized)

Two sections following decision D-07.

**Section header pattern** (identical for both):
- Flex row: section name (24px/700) + count badge (right-aligned)
- Count badge: Neo Brutalism Badge with count text (e.g., "12 transactions")
- 4px left border accent on the section header container:
  - Categorized: `green-600` (`#16a34a`)
  - Uncategorized: `amber-600` (`#d97706`)
- 16px left padding after the accent border
- 16px gap below header before table

**Transaction table** (D-08):
- Desktop: Neo Brutalism Table component
  - Columns: Date | Description | Amount (SGD) | Category
  - Column headers: 14px/700, `font-heading`
  - Date column: 14px/500, format "15 Mar 2026", width ~120px
  - Description column: 14px/500, flex-grow, truncate with ellipsis at 300px on desktop
  - Amount column: 14px/500, right-aligned, `tabular-nums`, width ~120px. Debits show as "$1,234.56", credits as "($89.00)"
  - Category column: Badge component. Categorized rows show category name in default Badge (amber bg). Uncategorized rows show a dash "--" in plain text (14px/500, 40% opacity)
  - Row height: 48px
  - Alternating row backgrounds: odd rows `bg-secondary-background`, even rows `bg-background` (matching Phase 1 user-table pattern)

- Mobile (< 768px, D-12): stacked cards
  - Each transaction is a Card with 16px padding
  - Layout: Description (14px/700, full width, first line), Date (14px/500, 40% opacity) on the next line, Amount (16px/700, right-aligned) on the same line as date, Category badge below
  - Cards have 8px gap between them

**Duplicate rows** (D-11):
- Duplicate transactions render in the table with `line-through` text decoration
- Row opacity reduced to 50%
- A small `AlertTriangle` icon (16px, amber) appears before the description
- Duplicates are NOT interactable (no hover effects, no selection)
- Duplicates appear in their natural position within the table, not grouped separately

### Duplicate Warning Banner

Displayed between the summary card and transaction sections when duplicates are detected (D-11).

- Full-width banner: white bg (`--secondary-background`), 2px border, `rounded-base`
- Left accent: 4px left border in amber (`#d97706`)
- Content: `AlertTriangle` icon (20px, amber) + warning text
- Warning text: "{N} transactions already imported and will be skipped." (14px/500)
- Padding: 16px

### Bottom Sticky Import Bar (D-10)

- Fixed to bottom of viewport, full width of the content area
- Height: 64px
- Background: white (`--secondary-background`), `border-t-2 border-border`, `shadow-shadow` (shadow goes upward: `0 -4px 0 0 var(--border)`)
- Content flex row with 16px horizontal padding:
  - Left: "{N} transactions ready" (16px/700) -- count excludes duplicates
  - Right: "Import {N} Transactions" button (amber accent, `variant="default"`)
- Button states:
  - Active: amber bg, "Import {N} Transactions" label, enabled when at least 1 non-duplicate transaction exists
  - Disabled: 50% opacity, "Import Transactions" label (no count when disabled) -- disabled until Phase 3 adds the 100% categorization gate (all transactions will be uncategorized in Phase 2, but button still works for raw import)
  - Loading: "Importing..." with `Loader2` spinner, disabled

**Phase 2 specific note:** Per D-10, the button is "disabled until Phase 3's 100% categorization gate." However, in Phase 2 there is no categorization yet, so the import button should be ENABLED -- it imports raw uncategorized transactions. The 100% gate will be layered in Phase 3. The sticky bar structure supports future Phase 3 additions (progress indicator, categorization count).

### Timeline Bar (D-15, IMPT-07)

A horizontal visualization of imported vs missing statement periods.

- Full-width container, white bg (`--secondary-background`), 2px border, `rounded-base`, 16px padding
- Heading: "Statement Coverage" (14px/700) above the bar
- 8px gap
- Bar: horizontal flex row of month segments
- Each segment: 32px height, flex-grow (equal width), 2px border between segments
  - **Filled** (month has imported data): `green-600` (`#16a34a`) background, white text
  - **Gap** (month missing): `red-500` (`#ef4444`) background at 20% opacity, black text
  - **Future** (month not yet reachable): `--secondary-background`, 40% opacity text
- Month label inside each segment: abbreviated month + year if January or first visible month (e.g., "Mar", "Jan 26"), 14px/500, centered
- Bar spans from the earliest imported statement month to the current month
- If fewer than 3 months of data, show a minimum of 6 month segments for visual context
- On mobile: bar wraps to 2 rows if more than 6 months, or scrolls horizontally

### Bank Config Viewer (`/settings/bank-configs`, D-18)

- Page heading: "Bank Configurations" (24px/700)
- Descriptive text: "Configured bank statement formats for parsing. Contact your admin for changes." (16px/500, 60% opacity)
- 24px gap
- One Card per bank config:
  - Card title: bank name (e.g., "Citibank SG Credit Card") (16px/700)
  - Card content: read-only key-value pairs of the config displayed in a definition list
    - Label (14px/700): "Date Format", "Credit Indicator", "Skip Patterns", etc.
    - Value (14px/500): the config value, monospace font (`font-mono`) for regex patterns
  - No edit controls (D-18: read-only in v1)
- If no configs: EmptyState with heading "No bank formats configured" and body "Bank format configurations will appear here once seeded."

## Responsive Behavior

Inherits from Phase 1 breakpoint at 768px (Tailwind `md`).

| Breakpoint | Layout Change |
|------------|--------------|
| >= 768px (md) | Full sidebar (260px) + content area with 32px padding. Tables rendered as tables. Summary card as 2x2 grid. Timeline bar as single row. |
| < 768px | Sidebar hidden (hamburger drawer). Content area full width with 16px padding. Tables transform to stacked cards. Summary card as single column (4 rows). Timeline bar wraps to 2 rows or scrolls horizontally. |

**Phase 2 mobile specifics:**
- Drop zone: minimum height reduces to 200px on mobile, same centered layout
- Collapsed summary bar: wraps to 2 lines (filename on line 1, "Upload another" on line 2)
- Sticky import bar: same height (64px), text truncates if needed, button remains full size
- Transaction cards: full width, 8px gap between cards, consistent with Phase 1 mobile card pattern

## Accessibility

Inherits all Phase 1 accessibility contracts. Phase 2 additions:

| Concern | Implementation |
|---------|---------------|
| Drop zone keyboard | Drop zone is focusable and activates file picker on Enter/Space. `aria-label="Upload PDF file"`. |
| Drop zone drag-and-drop | `aria-live="polite"` region announces state changes: "Drag active", "Parsing statement", "15 transactions parsed". |
| Duplicate rows | Duplicate rows have `aria-disabled="true"` and `aria-label` explaining "Duplicate -- already imported on {date}". |
| Sticky bar | `aria-live="polite"` announces transaction count changes. Import button has `aria-label="Import {N} transactions"`. |
| Timeline bar | Each segment has `role="img"` with `aria-label="{Month Year}: {status}"`. Container has `role="group"` with `aria-label="Statement coverage timeline"`. |
| Amount formatting | Amounts use `aria-label` with full text (e.g., `aria-label="One thousand two hundred thirty four dollars and fifty six cents, debit"`) via `Intl.NumberFormat` with `notation: 'standard'`. |
| Color independence | Categorized/uncategorized sections are distinguished by label text and icon, not only by border color. Timeline segments include text labels, not just color. |
| Screen reader table | Transaction tables use proper `thead`/`tbody` structure with `scope="col"` on headers (inherited from shadcn Table component). |
