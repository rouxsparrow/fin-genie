# Phase 1 — UI Design Contract

> Visual and interaction contract for the Foundation & Auth phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Login page, app shell (sidebar navigation + content area), dashboard empty state, settings page (user management), error page, loading skeletons, toast notifications.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui + neobrutalism registry |
| Preset | Neo Brutalism amber — `@neobrutalism/*` components via shadcn CLI |
| Component library | Radix UI (via shadcn primitives) |
| Icon library | lucide-react |
| Font | DM Sans (Google Fonts, `next/font/google`) |

**Setup sequence:** Initialize shadcn, replace `globals.css` with Neo Brutalism styling (amber variant), install `@neobrutalism/*` components as needed. The neobrutalism registry overrides shadcn defaults — do not mix base shadcn and neobrutalism variants of the same component.

## Typography

Font: **DM Sans** — loaded via `next/font/google` with `display: swap`, `subsets: ['latin']`, `adjustFontFallback: false`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 500 (medium) | 1.5 | Paragraphs, descriptions, table cells, form labels |
| Label | 14px | 500 (medium) | 1.4 | Input labels, sidebar items, badges, metadata |
| Heading | 24px | 700 (bold) | 1.2 | Page titles, card headings, section headers |

**Weight constraint:** Only 500 (medium) and 700 (bold) are used. Neo Brutalism `--heading-font-weight: 700` and `--base-font-weight: 500` are locked by the theme.

## Color

All colors use oklch values from the Neo Brutalism amber theme. CSS custom properties are defined in `globals.css` and consumed via Tailwind classes (`bg-main`, `bg-background`, `text-foreground`, etc.).

| Role | CSS Variable | oklch Value | Approx Hex | Usage |
|------|-------------|-------------|------------|-------|
| Dominant (60%) | `--background` | `oklch(96.22% 0.0569 95.61)` | #f5f0d0 | Page background, content area surface |
| Secondary (30%) | `--secondary-background` | `oklch(100% 0 0)` | #ffffff | Cards, sidebar background, input backgrounds, dialog surfaces |
| Accent (10%) | `--main` | `oklch(84.08% 0.1725 84.2)` | #e5c800 | See reserved-for list below |
| Foreground | `--foreground` | `oklch(0% 0 0)` | #000000 | Body text, headings, icons |
| Border | `--border` | `oklch(0% 0 0)` | #000000 | All borders (2px solid), box shadows |
| Overlay | `--overlay` | `oklch(0% 0 0 / 0.8)` | #000000cc | Mobile drawer backdrop, dialog backdrop |
| Destructive | n/a (inline) | — | #ef4444 | Remove user button, destructive confirmations only |

### Accent Reserved For

The amber accent (`--main`) is used exclusively on these elements:

1. **Primary action buttons** — Login button, Add User button, Save Settings button
2. **Active sidebar item** — background fill on the currently selected nav item
3. **Role badge (Admin)** — small badge in sidebar footer and user management table
4. **Toast success indicator** — left border accent on success toasts
5. **Empty state CTA button** — the action button in empty state cards

Accent is NOT used on: all buttons generically, links, borders, backgrounds, or decorative elements. Non-primary buttons use `--secondary-background` with `--border`.

## Neo Brutalism Styling Tokens

These are theme-level constants from the Neo Brutalism globals.css. They apply to all components.

| Token | Value | Usage |
|-------|-------|-------|
| `--box-shadow-x` | 4px | Horizontal shadow offset on cards, buttons, inputs |
| `--box-shadow-y` | 4px | Vertical shadow offset on cards, buttons, inputs |
| `--border-radius` | 5px | All rounded corners (mapped to `rounded-base`) |
| `--shadow` | `4px 4px 0px 0px var(--border)` | Hard drop shadow on all elevated elements |
| Border width | 2px | All borders use `border-2` (Tailwind class) |

**Hover interaction:** Buttons and clickable cards translate by `(box-shadow-x, box-shadow-y)` on hover, removing the shadow — creating a "pressed" effect. Implemented via `hover:translate-x-boxShadowX hover:translate-y-boxShadowY hover:shadow-none`.

**Focus ring:** `focus-visible:ring-2 focus-visible:ring-black focus-visible:ring-offset-2` on all interactive elements.

## Page Layouts

### Login Page (`/login`)

- Full viewport height, centered vertically and horizontally
- Warm cream background (`--background`)
- Single card (480px max-width) with 2px black border and 4px hard shadow
- Card content: "Fin Genie" display text (32px/700), 24px gap, email input, 16px gap, password input, 16px gap, login button (full width, amber accent), 16px gap, "Forgot password?" text link (14px, underline)
- Error message appears below the login button as red text (16px), not a toast
- No visible sign-up link (admin-only creation per D-12)

### App Shell (authenticated pages)

- No top header bar (D-08)
- Sidebar: 260px fixed width on desktop, white (`--secondary-background`) with 2px right border
- Content area: fills remaining viewport width, `--background` surface, 32px padding on desktop, 16px on mobile
- Sidebar header: "Fin Genie" in 24px/700 bold, 24px padding
- Sidebar nav: vertical list of items with 8px vertical gap between items
- Each nav item: 44px height, 16px horizontal padding, 14px/500 text, lucide icon (20px) + 12px gap + label
- Active item: amber (`--main`) background, black text, black border-2, hard shadow
- Disabled items: 50% opacity, cursor-not-allowed, still clickable (shows tooltip)
- Sidebar footer: 16px padding, top border separator, avatar initials circle (36px, amber bg, black border), full name (14px/700), role badge, logout button (ghost style, 14px)

### Navigation Items

| Order | Label | Icon (lucide) | Phase Available | Disabled in Phase 1 |
|-------|-------|---------------|-----------------|---------------------|
| 1 | Dashboard | `LayoutDashboard` | 1 (empty state) | No |
| 2 | Transactions | `Receipt` | 4 | Yes |
| 3 | Import | `Upload` | 2 | Yes (admin only) |
| 4 | Rules | `ListFilter` | 3 | Yes (admin only) |
| 5 | Categories | `Tags` | 3 | Yes (admin only) |
| 6 | Settings | `Settings` | 1 | No (admin only) |

**Viewer visibility:** Viewers see Dashboard, Transactions only. Import, Rules, Categories, Settings are hidden for viewers (D-05).

### Dashboard (empty state, `/dashboard`)

- Page heading: "Dashboard" (24px/700)
- Empty state card centered in content area (max-width 480px)
- Icon: `BarChart3` from lucide (48px, 50% opacity)
- Heading: "No spending data yet" (24px/700)
- Body: "Upload your first bank statement to start tracking where your money goes." (16px/500, 60% opacity)
- CTA button: "Import Statement" (amber accent, disabled for Phase 1 with tooltip "Available in the next update")
- For viewers: CTA reads "Ask your admin to import a statement" (no button, just text)

### Settings Page (`/settings`, admin only)

- Page heading: "Settings" (24px/700)
- Section heading: "Household Members" (20px/700), with "Add Member" button (amber accent) aligned right
- User table with columns: Name (14px/700), Email (14px/500), Role (badge), Actions
- Table rows: 2px border, alternating subtle background (every other row gets `--background` tint)
- Role badge: "Admin" (amber bg, black text, black border), "Viewer" (white bg, black text, black border)
- Actions column: "Remove" button (destructive variant, red text on hover)
- "Add Member" dialog: title "Add Household Member", fields (email, full name, role select), "Create Account" button
- Empty table state: "No other members yet. Add someone to share your spending data."

### Error Page

- Full viewport centered card (same layout as login)
- Icon: `AlertTriangle` from lucide (48px)
- Heading: "Something went wrong" (24px/700)
- Body: "We hit an unexpected error. Try refreshing, or head back to the dashboard." (16px/500)
- Two buttons: "Try Again" (amber accent, calls refresh), "Go to Dashboard" (secondary, navigates to `/dashboard`)

## Responsive Behavior

| Breakpoint | Layout Change |
|------------|--------------|
| >= 768px (md) | Full sidebar (260px) + content area |
| < 768px | Sidebar hidden, hamburger icon (top-left, 44px touch target), Sheet/drawer overlay (280px width, slides from left) |

**Mobile content area:** Full width, 16px padding. Tables transform to stacked cards — each row becomes a card with label/value pairs stacked vertically.

## Accessibility

| Concern | Implementation |
|---------|---------------|
| Focus management | Focus trapped in modal dialogs and mobile drawer. Return focus to trigger on close. |
| Keyboard navigation | Tab through sidebar items, Enter/Space to activate. Escape closes dialogs/drawer. |
| Screen reader | Sidebar uses `nav` landmark with `aria-label="Main navigation"`. Disabled items have `aria-disabled="true"`. Role badges have `aria-label` (e.g., "Role: Admin"). |
| Color contrast | Black text (#000) on amber (#e5c800) = 8.2:1 ratio (WCAG AAA). Black text on cream bg (#f5f0d0) = 16.4:1 (WCAG AAA). |
| Reduced motion | Respect `prefers-reduced-motion`: disable hover translations and toast slide animations. |

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | button, card, input, label, select, table, dialog, badge, tooltip, separator, skeleton, sonner, sheet | not required |
| neobrutalism.dev (`@neobrutalism/*`) | button, card, input, label, select, table, dialog, badge, tooltip, separator, skeleton, sonner, sheet | third-party — vetting required at execution time |

**Registry vetting note:** The `@neobrutalism/*` components are installed via the shadcn CLI (`npx shadcn add @neobrutalism/<component>`). Each component must be vetted with `npx shadcn view @neobrutalism/<component>` before installation during execution. The executor must scan for `fetch(`, `eval(`, `process.env`, dynamic imports from external URLs, and obfuscated code. If any flags are found, the developer must review and approve before the component enters the codebase.
