    **1. `fetchDashboardStats(from: string, to: string)`** — Returns stats for D-01 stat cards:
    - Total spending: `SUM(amount_cents)` from transactions WHERE `is_debit = true` AND `transaction_date BETWEEN from AND to` AND category is NOT is_system (exclude Card Payment). Use a join: `.select('amount_cents, categories!inner(is_system)')` with `.eq('categories.is_system', false)` OR use an RPC. Simpler approach: fetch the "Card Payment" category ID first (`.from('categories').select('id').eq('is_system', true).eq('name', 'Card Payment').single()`), then exclude it with `.neq('category_id', cardPaymentId)`.

    - Monthly average: `SUM / count of distinct months` across all transactions (not just the range).
    - Top category: `GROUP BY category_id, SUM(amount_cents) ORDER BY sum DESC LIMIT 1` — use Supabase RPC or fetch all category totals and pick max in JS.
    - Largest transaction: `ORDER BY amount_cents DESC LIMIT 1` within range, excluding Card Payment category.
    - Recurring spend: `SUM(amount_cents)` WHERE category name = 'Subscriptions' AND within date range.

    Since Supabase JS client doesn't support GROUP BY natively, use this approach:
    - Fetch all debit transactions in range (excluding Card Payment category) with their category_id
    - Compute aggregations in JS (SUM, GROUP BY, MAX, etc.)
    - This is acceptable for a household app with < 10k transactions

    Uses nuqs `useQueryStates` (or `parseAsString` builders) to manage URL params:
    ```typescript
    import { useQueryStates, parseAsString } from 'nuqs';
    import { startOfMonth, endOfMonth, subMonths, startOfYear, format } from 'date-fns';

    export type DatePreset = 'this-month' | 'last-3-months' | 'last-6-months' | 'this-year' | 'custom';

    export function useDateRange() {
      const today = new Date();
      const defaultFrom = format(startOfMonth(today), 'yyyy-MM-dd');
      const defaultTo = format(endOfMonth(today), 'yyyy-MM-dd');

      const [params, setParams] = useQueryStates({
        from: parseAsString.withDefault(defaultFrom),
        to: parseAsString.withDefault(defaultTo),
        preset: parseAsString.withDefault('this-month'),
      });

      function setPreset(preset: DatePreset) {
        const now = new Date();
        let from: Date, to: Date;
        switch (preset) {
          case 'this-month':
            from = startOfMonth(now); to = endOfMonth(now); break;
          case 'last-3-months':
            from = startOfMonth(subMonths(now, 2)); to = endOfMonth(now); break;
          case 'last-6-months':
            from = startOfMonth(subMonths(now, 5)); to = endOfMonth(now); break;
          case 'this-year':
            from = startOfYear(now); to = endOfMonth(now); break;
          default:
            return; // custom handled separately
        }
        setParams({ from: format(from, 'yyyy-MM-dd'), to: format(to, 'yyyy-MM-dd'), preset });
      }

      function setCustomRange(from: Date, to: Date) {
        setParams({ from: format(from, 'yyyy-MM-dd'), to: format(to, 'yyyy-MM-dd'), preset: 'custom' });
      }

      return {
        from: params.from,
        to: params.to,
        preset: params.preset as DatePreset,
        setPreset,
        setCustomRange,
      };
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> analytics server actions | User-supplied date range params (from, to) and search/filter params cross into server |
| URL params -> component state | URL query params (?from, ?to, ?search) are user-controlled input rendered in UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | analytics-actions.ts | mitigate | verifyAuthenticated() checks Supabase auth session at start of every server action; RLS policies on transactions table enforce household_id scoping |
| T-04-02 | Tampering | analytics-actions.ts (date params) | mitigate | Validate from/to params are valid ISO date strings (YYYY-MM-DD format check) before passing to Supabase .gte/.lte queries |
