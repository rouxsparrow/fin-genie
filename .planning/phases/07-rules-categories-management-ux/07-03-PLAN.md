<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser -> `importUserRules` | Untrusted parsed JSON crosses into server-side Zod validation. |
| `importUserRules` -> Supabase categories/rules tables | Destructive replace-mode writes cross into persistent household data. |
| `previewRecategorization`/`applyRecategorization` -> Supabase transactions table | Rule evaluation results cross into transaction category writes only for apply. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 | Elevation of Privilege | New rule server actions | mitigate | Every new action must call `verifyAdmin()` before database access. |
| T-07-10 | Tampering | `importUserRules` replace mode | mitigate | Require exact `REPLACE USER RULES` confirmation, validate payload with Zod, validate regexes, create/resolve categories, build insert rows, then delete only `.eq('household_id', householdId).eq('is_system', false)` rules. |
| T-07-11 | Tampering | System rules | mitigate | Export and import only rows with `is_system=false`; imported rows must always insert `is_system: false`. |
| T-07-12 | Denial of Service | JSON import payload | mitigate | Cap rules at 500, pattern at 200 chars, category name at 50 chars, and reject invalid regexes before database writes. |
| T-07-13 | Information Disclosure | `exportUserRules` | mitigate | Select only household-scoped user rules and category names after `verifyAdmin`; do not export IDs, household IDs, or system rules. |
| T-07-14 | Repudiation | Replace import | accept | This phase has no audit-log requirement; mitigation is destructive confirmation and returned `imported`/`createdCategories` counts. |
| T-07-15 | Tampering | Recategorization preview/apply drift | mitigate | Apply recomputes from live data and returns final updated/unchanged counts; preview is explicitly read-only. |
</threat_model>
