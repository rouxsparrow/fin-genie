| Boundary | Description |
|----------|-------------|
| Admin browser -> rules client components | User-entered rule patterns and category selections enter client validation before server action submission. |
| Rules client components -> server actions | Server actions remain the authority for admin authorization and household-scoped writes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `RuleEditForm` duplicate validation | mitigate | Add client duplicate feedback for pattern+match type, while preserving existing server validation as the source of truth. |
| T-07-02 | Elevation of Privilege | `RuleRow`/`RulesTable` system rules | mitigate | Keep system rows disabled and visibly marked with `Protected system rule`; no edit/delete/reorder handlers become enabled for `rule.is_system`. |
| T-07-03 | Spoofing | Mobile rule cards | mitigate | System cards must include text `Protected system rule` so a locked row is not represented only by an icon. |
| T-07-04 | Information Disclosure | Rule/category scan labels | accept | Rule patterns and category names are already visible to authenticated admins on `/rules`; this plan does not expand access. |
