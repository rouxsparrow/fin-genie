<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin filesystem -> browser JSON parser | A selected local JSON file becomes untrusted client data. |
| Browser JSON payload -> `importUserRules` | Parsed JSON crosses into server validation and destructive replace-mode behavior. |
| Browser -> recategorization server actions | Admin confirmation triggers broad transaction category updates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-16 | Tampering | `RuleImportExport` JSON import | mitigate | Client requires exact `REPLACE USER RULES` before calling server import; server still validates exact confirmation. |
| T-07-17 | Denial of Service | Browser file import | mitigate | Accept only `.json`/`application/json` in file picker and rely on Plan 03 Zod max limits server-side. |
| T-07-18 | Spoofing | Import/replace dialog | mitigate | Dialog title and copy explicitly say replace is destructive and category names are used; no hidden one-click import. |
| T-07-19 | Repudiation | Recategorization apply | mitigate | Preview dialog shows changed count/sample before apply; final toast reports updated and unchanged counts. |
| T-07-20 | Elevation of Privilege | Import/export UI | mitigate | UI calls only Plan 03 server actions, which must call `verifyAdmin`; this component does not attempt direct Supabase writes. |
</threat_model>
