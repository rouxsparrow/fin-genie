<objective>
Allow uploading multiple PDF files at once on the import page. The drop zone accepts
multiple files, and the system processes them sequentially — parse, review/categorize,
import — one file at a time. A file queue progress indicator shows "File N of M"
throughout the flow.

Purpose: Users often have several months of statements to import. Forcing one-at-a-time
upload-then-reset is tedious. Multi-file queuing lets them drop all files at once and
work through them sequentially.

Output: Updated import page with multi-file support.
</objective>

**State changes in `src/app/(authenticated)/import/page.tsx`:**

1. Replace `ImportPageState` with a queue-aware state:

```typescript
interface FileQueueItem {
  file: File;
  fileName: string;
}

interface ImportPageState {
  status: ImportPageStatus; // same enum: 'idle' | 'parsing' | 'review' | 'importing' | 'error'
  queue: FileQueueItem[];   // all files to process
  currentIndex: number;     // index of file currently being processed (0-based)
  parseResult: (ParseResult & { duplicateHashes: string[] }) | null;
  error: { code: string; message: string } | null;
}
```

The `currentIndex` combined with `queue` lets us derive: current file name (`queue[currentIndex].fileName`),
file position display (`currentIndex + 1` of `queue.length`), and whether more files remain
(`currentIndex < queue.length - 1`).

2. `handleFilesSelected(files: File[])`: Build the queue from the files array. Set
   `currentIndex: 0`, `status: 'parsing'`. Immediately call the parse logic for the first file.
   Sort files alphabetically by name so the processing order is predictable.

3. `handleFileSelected` is removed (replaced by `handleFilesSelected`).

4. Parsing: `handleParseCurrentFile()` — reads `queue[currentIndex].file`, creates FormData,
   calls `parseStatement`. On success -> status: 'review'. On error -> status: 'error'.

5. `handleImport()`: Same logic as now. After successful import, call `advanceToNextFile()`.

6. `advanceToNextFile()`: If `currentIndex < queue.length - 1`, increment `currentIndex`,
   reset `parseResult`, `categoryMap`, set `status: 'parsing'`, and call `handleParseCurrentFile()`.
   If no more files, reset to `initialState` (idle).

7. `handleReset()`: Resets everything back to `initialState` (clears the entire queue).

8. `handleSkipFile()`: Advances to next file without importing. Uses same `advanceToNextFile()` logic.
   Wire this to the `onUploadAnother` prop of `ReviewScreen` — but only when there are more files
   in queue. When it's the last file (or single file), `onUploadAnother` still resets to idle.

9. **File queue progress indicator**: When `queue.length > 1`, render a small progress bar/indicator
   above the current step (parsing, review, etc.) showing "File N of M". Use a simple styled div:

```tsx
{queue.length > 1 && (
  <div className="flex items-center gap-3 rounded-base border-2 border-border bg-secondary-background px-4 py-2">
    <span className="text-sm font-bold">
      File {currentIndex + 1} of {queue.length}
    </span>
    <div className="h-2 flex-1 overflow-hidden rounded-full border border-border">
      <div
        className="h-full bg-main transition-all duration-300"
        style={{ width: `${((currentIndex + 1) / queue.length) * 100}%` }}
      />
    </div>
  </div>
)}
```

   Place this between the page header and the current status content (drop zone / progress / review / error).

10. Update the `<PdfDropZone>` call to use the new prop: `onFilesSelected={handleFilesSelected}`.

11. On the error screen, add a "Skip & Continue" button (in addition to "Upload Again") when there
    are remaining files in the queue. "Upload Again" resets the whole queue. "Skip & Continue"
    calls `advanceToNextFile()`. When it's a single file or the last file, only show "Upload Again".

12. After the last file is successfully imported, show a summary toast:
    `toast.success('All N files processed.')` in addition to the per-file import toast.
